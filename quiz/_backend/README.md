# クイズ回答の記録（バックエンド設定手順）

- 目的: クイズページの回答をフォーム回答シートへ記録する Apps Script の設定・更新手順
- 対象読者: 採用担当（このクイズを運用する人）
- 制約: 正解（答え）を書かない（公開リポ）

クイズページ（`quiz/index.html`）の回答を、**既存のフォーム回答シート**（gid=1642761423 のタブ）の末尾に1行ずつ追記する。
採点（スコア・点数）は**シート側の既存の関数に任せる**。このスクリプトは正解を持たず、採点もしない。

`_backend/` はGitHub Pages では使わない設定用ファイル置き場。公開ページの動作には影響しない。

---

## 列マッピング（書き込む列だけ）

```
A  タイムスタンプ        ← 送信時刻（自動）
B  スコア               ← 触らない（フォームだった時期の値。非表示）
C  氏名を記入してください ← 氏名
D  職種                 ← 職種（Product Engineer / Design Engineer / BizOps）
E  点数(100)            ← 触らない（シートの関数）
F  01(5)               ← 第1問で選んだ番号(1〜12)
G  02(2)               ← 第2問
H  03(10)              ← 第3問
I  04(6)               ← 第4問
J  05(9)               ← 第5問
K  06(12)              ← 第6問
L  07(13)              ← 第7問
M  08(15)              ← 第8問
N〜U 時間01〜時間08      ← 第1〜8問の所要時間（秒）
V  削除06(11)           ← 触らない（差し替え前の第6問。非表示）
```

- 番号を選ばなかった問題は 0。送信に無い問題（6問だった時期のページからの第7〜8問）は番号・時間とも空欄。
- **B・E・V は書き込まない**ので、そこに入っている関数は壊れない。
- 列の並びを変える時は、`Code.gs` の書き込む列も同時に直してデプロイし直す（列は番号で書いている）。

## 事前準備（1回だけ）

- **見出し行（3行目）に、上の列マッピングの見出しを入れておく**（追記先の見出しに合わせるため）。正解は2行目の F〜M に置く。
- 回答の範囲はテーブルになっていて、E（点数）は行ごとの関数。新しい行が追記されると、テーブルが同じ関数を自動で入れる。
- E の関数は8問で計算し、M列が空欄の行（6問だった時期の回答）は6問で計算する。点数は ROUND で整数にする（切り捨て・INT は使わない）。

## 1. Apps Script を貼り付け

1. 対象スプレッドシートを開く → メニュー「拡張機能」→「Apps Script」
2. エディタの中身を全部消して、`Code.gs` の内容を貼り付け → 保存（💾）

## 2. ウェブアプリとしてデプロイ

1. 右上「デプロイ」→「新しいデプロイ」
2. 種類（⚙️）→「ウェブアプリ」
3. 設定:
   - 次のユーザーとして実行: **自分**
   - アクセスできるユーザー: **全員**  ← 匿名の受験者が送信できるように
4. 「デプロイ」→ 初回は権限承認を許可
5. 表示される **ウェブアプリ URL**（`https://script.google.com/macros/s/..../exec`）をコピー

コードを更新する時は「デプロイ」→「デプロイを管理」→ 既存のデプロイを編集 → バージョン「新バージョン」→「デプロイ」。URL は変わらない（「新しいデプロイ」を作ると URL が変わり、ページは古いコードへ送り続ける）。

## 3. URL をクイズページに設定

`quiz/index.html` の先頭付近、`var ENDPOINT = "";` に URL を貼る:

```js
var ENDPOINT = "https://script.google.com/macros/s/..../exec";
```

→ コミット＆プッシュすれば本番送信が有効になる。

> 動作確認: ウェブアプリ URL をブラウザで直接開くと「OK: クイズ回答受信エンドポイントです。」と出ればデプロイ成功。
> 実テスト: クイズを1回通すと、フォーム回答シートの末尾に1行追加され、D に職種、F〜M に選んだ番号、N〜U に所要時間が入る。
